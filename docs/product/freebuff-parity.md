# Coderax and Freebuff feature parity

Research checked on 2026-10-27 against Freebuff's official product pages, public repository README, plans, Terms, and Privacy Policy, and the current Coderax `main` source and release. This is a capability comparison, not a request to copy Freebuff's code, branding, interface, inference service, or business model. Coderax should use original implementation and preserve its provider choice, self-hosting, access controls, and user approvals.

## Product comparison

## Practical sequence

1. **Desktop distribution:** current Windows x64 release and README link are in place. Run packaging tests on pull requests; then add macOS, Linux, and Windows Arm64 builds, including signed/notarized release credentials where needed.
2. **Local coding:** add a CLI and workspace workflow that reuse Coderax's auth and agent contracts. Keep file and command access explicit, limited to the chosen project, and reviewable.
3. **Hosted code workspaces:** add tenant-scoped repository connections, isolated disposable environments, previews, audit, approval, and cleanup before offering Cloud-style execution.
4. **Connectors and mobile:** build a least-privilege OAuth catalog and mobile task review surface against stable APIs.
5. **App Builder and managed inference:** treat provisioning and paid inference as separate products requiring customer-owned infrastructure choices, model/provider agreements, capacity limits, and billing controls.

The Freebuff Terms limit free inference to normal use of official Freebuff products and prohibit direct endpoints, wrappers, and automated product use. Coderax must use its own supported providers and original implementation. This matrix does not claim parity for the missing CLI, native mobile apps, App Builder, hosted GitHub workspaces, multi-platform desktop packages, one-click connector catalog, or included model usage.
